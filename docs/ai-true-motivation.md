# ИИ-помощник истинной мотивации в ProfZOR

Спецификация того, что нужно реализовать в **текущей** программе (статический HTML/CSS/JS + LocalStorage), чтобы подключить ИИ как второго эксперта за плечом интервьюера — не как автодиагноз.

Документ написан с позиции пользователя, который ведёт живое интервью по 7 радикалам и должен отделить **заявленную** мотивацию от **истинной**.

---

## 1. Как я работаю сейчас

Живое интервью — это не заполнение анкеты. Я слушаю, коротко пишу, решаю, к какому радикалу относится кусок речи, и иду дальше.

Текущий поток:

1. Слева — код респондента, дата и 12 общих вопросов (шпаргалка).
2. В центре — сырые заметки. Новый текст после предыдущего клика переносится в наблюдения выбранного радикала.
3. Справа — «Вопросы для проверки» активного радикала и уже перенесённые наблюдения.
4. На вкладке «Карточка профиля» радикалы сортируются **по числу наблюдений**. Кнопка «Сформировать предварительное заключение» склеивает этот рейтинг в шаблон.

Что я как интервьюер реально делаю руками и головой:

- решаю, какой вопрос задать следующим;
- ловлю социально желательные ответы («хочу развиваться», «команда», «польза»);
- отличаю содержание ответа от **способа** говорить (темп, оценки, что выпячивает, что обходит);
- кликаю радикал, когда услышал маркер;
- в конце собираю иерархию и уже из неё вывожу, **чем человека на самом деле двигает**.

Истинная мотивация в методе 7 радикалов — не отдельное поле «мотивы». Это вывод из ведущих радикалов плюс расхождение между красивой речью и устойчивыми маркерами характера.

## 2. Где текущая программа меня не держит

| Что нужно на интервью | Что есть сейчас | Почему ИИ сюда не подключить |
|---|---|---|
| Связка «вопрос → ответ → маркер» | Один сплошной текст заметок + клик по радикалу | Модель не знает, на какой вопрос был ответ |
| Отметить, какие общие вопросы уже заданы | Список без галочек и без ответов | Нельзя считать покрытие и просить «добивающий» вопрос |
| Банк проверочных вопросов по радикалам | Пустой (`buildDefaultCheckBank()` возвращает `[]`) | Нечем подсказывать проверку гипотезы |
| База маркеров радикала | Только имя и цвет | ИИ не знает, *что* считать истероидом, эпилептоидом и т.д. |
| Заявленное vs наблюдаемое | Одно поле `observations[].text` | Нельзя сравнить «хочу помогать» с реальной речью |
| Невербалика / поведение | Нет типа источника | Теряется то, что часто правдивее слов |
| Иерархия по силе, не по кликам | Сортировка `sortOrderByObservationCount` | Кто чаще кликнут — тот «ведущий». Это артефакт скорости записи, не портрет |
| Выраженность и уверенность | `intensity` живёт в данных, в UI интервью не редактируется; `confidence` убран | Некуда положить оценку эксперта и оценку ИИ раздельно |
| Заключение | Шаблон «зафиксировано наблюдений: N» | Это оглавление, а не гипотеза мотивации |
| Граница ответственности | Честный дисклеймер в шапке | Любой ИИ обязан остаться слоем *предложений*, которые я подтверждаю |

Вывод: подключать модель к текущему JSON интервью почти бесполезно. На вход уйдёт каша из заметок и счётчиков. На выходе будет правдоподобный текст, который нельзя проверить.

## 3. Что такое «истинная мотивация» в этой программе

Для ProfZOR фиксируем рабочее определение.

**Заявленная мотивация** — то, что респондент называет сам: профессии, качества, «что нравится в работе», социально одобряемые формулировки.

**Истинная мотивация** — устойчивый драйвер, который следует из ведущих радикалов и из того, на чём человек оживает, чего избегает, что выводит из равновесия. Её не спрашивают в лоб.

Типичные драйверы (знания для ИИ и для эксперта, не диагноз):

| Радикал | Истинный драйвер (гипотеза) | Как маскируется в речи |
|---|---|---|
| Истероид | Признание, сцена, уникальность образа | «Хочу вдохновлять», «быть лицом продукта» |
| Эпилептоид | Контроль, порядок, «моё», правила | «Люблю процессы», «отвественность» |
| Паранойал | Идея, цель, влияние на ход дела | «Стратегия», «миссия», «хочу менять систему» |
| Шизоид | Понимание, автономия, свой интерес | «Глубокая экспертиза», «сложные задачи» |
| Гипертим | Движение, новизна, свобода действия | «Динамика», «не люблю рутину» |
| Эмотив | Сохранение отношений, не причинить вред | «Команда», «атмосфера», «помогать людям» |
| Тревожный | Безопасность, предсказуемость, одобрение | «Стабильность», «понятные требования» |

ИИ имеет право предлагать **гипотезу** вида:

> Заявлено: развитие и польза людям.  
> По маркерам вероятнее: признание + контроль территории (истероид + эпилептоид).  
> Что проверить: конкретный провал, реакция на критику, что делает без зрителя.

ИИ **не имеет права** записывать это в заключение без моего подтверждения.

## 4. Принципы встраивания (не ломать живое интервью)

1. **Эксперт подтверждает всё.** Как в шапке программы: оценки и выводы подтверждает пользователь. Предложение ИИ — отдельный слой, не замена клика по радикалу.
2. **Живое интервью не ждёт сеть.** Печать в «Сырые заметки» и клик по радикалу остаются мгновенными. Запрос к модели — фоном или по кнопке.
3. **Данные не уезжают сами.** Сейчас всё в LocalStorage. Вызов API — только после явного согласия на *это* интервью и с ключом, который хранится локально.
4. **Не лечить иерархию числом кликов.** ИИ и эксперт опираются на маркеры и расхождения, не на `observations.length`.
5. **Не возвращать сервер, кабинет и ленту промтов.** Текущий продукт — локальный инструмент. ИИ подключается тонким клиентом, без Next.js/БД.

## 5. Что реализовать в текущей программе

Работы три слоя. ИИ — третий. Первый и второй нужны даже без модели: без них помощник гадает.

### Слой A. Данные, без которых ИИ слеп

Расширить модель интервью (`collectInterview` / `emptyInterview` в `app.js`, чистые функции — в `interview-logic.js`). Старые сохранения мигрировать мягко.

#### A1. Протокол хода интервью

Сейчас общие вопросы — декоративная шпаргалка. Нужно:

- у вопроса: `asked`, `askedAt`, `answerId` (ссылка на фрагмент протокола);
- клик по вопросу = «задаю этот» (не удаление, не редактирование — интервьюер не должен возиться со списком во время беседы);
- визуально: заданный / не заданный, как чек-лист, без тяжёлого CRUD.

Проверочные вопросы радикала — тот же контракт: `asked` + привязка к радикалу (уже есть `radicalId`).

#### A2. Фрагмент протокола вместо «просто текст»

Каждое наблюдение должно уметь хранить:

```text
id, text, createdAt, order
radicalId            — назначение ЭКСПЕРТА (как сейчас, клик по чипу)
source               — general_question | check_question | free_note | behavior
questionId           — если ответ на конкретный вопрос
declaredMotiveHint   — если эксперт пометил фразу как заявленный мотив
socialDesirability   — none | suspected | confirmed (эксперт)
aiSuggestion         — слой ИИ, см. ниже, не смешивать с radicalId
```

Невербалика (`behavior`): «долго молчал», «заговорил быстрее», «ушёл в детали процедуры». Для мотивации это часто сильнее содержания.

#### A3. Слой предложений ИИ (отдельно от фактов)

```text
ai:
  status: idle | pending | ready | error
  updatedAt
  radicalHypotheses[]    — { radicalId, confidence, markers[], quoteIds[] }
  declaredMotives[]      — формулировки из речи
  trueMotiveHypothesis   — { drivers[], leadingRadicals[], tension[], confidence }
  contradictions[]       — { whatDeclared, whatObserved, whyItMatters, probeQuestion }
  coverageGaps[]         — каких радикалов/маркеров не хватает
  nextQuestions[]        — 1–3 вопроса, которые я могу задать сейчас
  disclaimer             — всегда: гипотеза, не диагноз
```

`radicalId` эксперта и `ai.radicalHypotheses` **не перезаписывают друг друга**. Если я кликнул «эпилептоид», а ИИ предлагает «тревожный», оба факта видны.

#### A4. Мотивация как сущность профиля

На карточке профиля, не в сырых заметках:

- `motivation.declared` — что назвал сам (можно заполнить вручную или принять из ИИ);
- `motivation.hypothesized` — черновик ИИ;
- `motivation.confirmed` — то, что я утвердил;
- `motivation.tensions` — список расхождений.

Пока `confirmed` пуст, в скачиваемом `.txt` мотивация либо отсутствует, либо помечена как «не подтверждена экспертом».

#### A5. База знаний радикалов в самом приложении

Новый модуль, например `radicals-knowledge.js` (подключается как `interview-logic.js`):

- речевые маркеры;
- поведенческие маркеры;
- типичный истинный драйвер;
- типичные социально желательные маски;
- 5–8 **дефолтных** проверочных вопросов на радикал.

Без этого файла системный промпт будет выдумывать характерологию. Банк `checkQuestionsBank` при пустом массиве сидится из этой базы (по тому же правилу, что 12 общих вопросов: не затирать непустой пользовательский список).

### Слой B. UI, который я успеваю использовать руками

Живой экран интервью уже плотный (3 колонки). ИИ нельзя впихнуть четвёртой колонкой.

#### B1. Вкладка «Интервью» — только шёпот, не кабинет аналитика

- Общие вопросы: галочка «задан».
- После клика по радикалу (как сейчас) опционально показать 1 строку: «ИИ: скорее эпилептоид (порядок, “должен”) — принять / другой / скрыть». Не блокирует фокус в заметках.
- Кнопка **«Подсказка ИИ»** (не автозапуск на каждый символ): анализирует *новую дельту* или весь протокол по выбору.
- Блок **«Что спросить дальше»** — 1–3 коротких вопроса. Клик копирует формулировку в заметки или в буфер. Не подменяет список проверки.
- Индикатор покрытия: какие радикалы без маркеров — уже почти есть в «Готовности профиля», но на вкладке интервью его не видно. Нужна компактная строка: «нет опоры: паранойал, шизоид».

#### B2. Вкладка «Карточка профиля» — место для мотивации

Добавить секцию **«Мотивация»** над или сразу под сводной таблицей:

1. Заявленное (цитаты).
2. Гипотеза ИИ (драйверы + ведущие радикалы + уверенность).
3. Расхождения.
4. Кнопки: «Подтвердить гипотезу», «Править», «Отклонить».
5. Только после подтверждения текст попадает в заключение.

Кнопку «Сформировать предварительное заключение» расширить: если есть подтверждённая мотивация — отдельный абзац; если только гипотеза ИИ — абзац с пометкой «не подтверждено»; если ничего — как сейчас, без выдумок.

Индикатор готовности: мало наблюдений *или* нет ни одного расхождения/проверки заявленного мотива → «для вывода об истинной мотивации данных недостаточно».

#### B3. Настройки ИИ (минимум)

Не отдельный продукт. Скрытый блок или маленькая панель:

- ключ API (LocalStorage, не в репозиторий);
- провайдер (сначала один: совместимый с OpenAI Chat Completions);
- тумблер «отправлять сырые заметки / только структурированный протокол»;
- тумблер «не вызывать ИИ автоматически»;
- кнопка «Собрать пакет без отправки» — копирует JSON+промпт, если сеть или ключа нет.

### Слой C. Клиент ИИ

Новые файлы, без сборки:

| Файл | Зачем |
|---|---|
| `radicals-knowledge.js` | Маркеры, драйверы, дефолтные проверочные вопросы |
| `ai-packet.js` | Собрать канонический пакет интервью для модели (чисто, тестируется как `interview-logic.js`) |
| `ai-prompts.js` | Системный и пользовательский промпт, JSON-схема ответа |
| `ai-client.js` | `fetch` к API, таймаут, разбор JSON, ошибки |

#### C1. Пакет на вход модели

Не отправлять «весь LocalStorage». Канонический пакет:

- код/дата (без лишних ПДн, если эксперт не вписал фамилию — тем лучше);
- список вопросов с флагами asked;
- фрагменты протокола: текст, source, questionId, radicalId эксперта;
- **не** отправлять `motivation.confirmed` прошлого захода как истину — иначе модель поддакивает;
- инструкция: опираться только на маркеры из `radicals-knowledge`, не ставить диагноз, не выдумывать цитаты.

#### C2. Что модель обязана вернуть

Строгий JSON (не свободное эссе):

- `declaredMotives[]`
- `radicalHypotheses[]` (не больше 3, с цитатами-id)
- `trueMotiveHypothesis`
- `contradictions[]`
- `coverageGaps[]`
- `nextQuestions[]` (короткие, можно задать вслух)
- `insufficientEvidence` (boolean)

Если `insufficientEvidence: true` — не заполнять «истинную мотивацию» красивым текстом.

#### C3. Когда вызывать

| Момент | Режим |
|---|---|
| Во время беседы | Только по кнопке «Подсказка ИИ» по последней дельте + уже известному протоколу |
| Перед сменой вопроса | По желанию: «что проверить» |
| На вкладке профиля | «Разобрать мотивацию» по всему протоколу |
| Формирование заключения | Использовать уже сохранённый `ai` + `motivation.confirmed`, новый вызов не обязателен |

Автоанализ на каждый `input` в textarea — запрещён: шум, деньги, утечка черновика, лаг.

#### C4. Системный промпт (смысл, не текст для копирования в чат)

Роль: ассистент эксперта по 7 радикалам.  
Задача: помочь отличить заявленную мотивацию от гипотезы истинной.  
Запреты: диагноз, уверенные формулировки без цитат, переписывание назначения эксперта, ранжирование по числу наблюдений.  
Стиль: короткие гипотезы, маркеры, один следующий вопрос.

## 6. Чего не делать

- Не ставить ИИ судьёй и не менять дисклеймер шапки.
- Не сортировать сводную таблицу по уверенности модели вместо экспертных наблюдений (можно *дополнительная* колонка «гипотеза ИИ», не замена ранга).
- Не автокликать радикал по ответу модели.
- Не возвращать облачный кабинет, ленту промтов и БД ради этой фичи.
- Не слать полное ФИО и чужие интервью «по умолчанию».
- Не генерировать заключение целиком нейросетью и подставлять в `#card-draft` без просмотра.
- Не имитировать мотивацию по пустому протоколу.

## 7. Порядок реализации (чтобы можно было вводить постепенно)

Каждый шаг уже полезен интервьюеру даже до появления ключа API.

1. **Протокол и покрытие**  
   Галочки «вопрос задан», тип источника наблюдения, дефолтные проверочные вопросы из базы знаний.  
   Критерий: я вижу, какие диагностические зоны пустые, не заходя в профиль.

2. **Пакет и промпт без сети**  
   Кнопка «Собрать пакет для ИИ» копирует структурированный текст. Эксперт может вставить его в любую модель вручную.  
   Критерий: пакет читается человеком и парсится тестом; в нём есть вопросы, ответы, назначения эксперта, пустые зоны.

3. **Опциональный вызов API**  
   Ключ локально, кнопка «Подсказка», разбор JSON в `ai.*`, UI «шёпот» + секция мотивации.  
   Критерий: отказ сети не ломает интервью; предложение не пишется в `radicalId`.

4. **Заключение**  
   Абзац мотивации только из `motivation.confirmed`; гипотеза ИИ — отдельно и с оговоркой.  
   Критерий: скачанный `.txt` не выдаёт догадку модели за вывод эксперта.

5. **Позже, не в первом подключении**  
   Голос/транскрипт, сравнение двух интервью, обучение на моих разметках, возврат поля «Цель интервью» как контекста для ИИ.

## 8. Как проверить, что помощник помогает, а не мешает

Сценарий живого интервью (ручной):

1. Открыть новое интервью, задать «Расскажите немного о себе», записать ответ, кликнуть радикал — как сейчас, без ожидания сети.
2. Нажать «Подсказка ИИ» — появляется гипотеза и 1 вопрос, фокус остаётся в заметках.
3. Задать социально желательный ответ («хочу помогать людям») — ИИ должен предложить проверку примером/границей, а не поверить формулировке.
4. На профиле: заявленное ≠ гипотеза; без моего «Подтвердить» в `.txt` нет фразы «истинная мотивация: …» как факта.
5. Выключить сеть / убрать ключ — интервью, клики, сохранение LocalStorage работают.

Автотесты (vitest, как сейчас для `interview-logic.js`):

- сборка пакета: вопрос без ответа не считается покрытым;
- миграция старого `observations: [{ text }]` → новый фрагмент с `source: free_note`;
- модель-заглушка с лишними полями не затирает `radicalId` эксперта;
- `insufficientEvidence` не записывает `motivation.hypothesized` как готовый вывод;
- заключение: confirmed / только AI / пусто — три разных текста.

| `tests/` | Пакет, миграция, заключение, изоляция ai от radicalId |
| новый `radicals-knowledge.js` | Маркеры и дефолтные проверки |
| новые `ai-packet.js`, `ai-prompts.js`, `ai-client.js` | Граница с моделью |

Ключи LocalStorage лучше не ломать: `profzor_last_interview_v2` расширяется полями. Черновик заметок `profzor_raw_draft_v1` не отправлять в API.

## 10. Короткий ответ на вопрос «что реализовать»

Чтобы ИИ помогал выявлять истинную мотивацию, в текущей ProfZOR нужно не «кнопку ChatGPT», а:

1. превратить заметки в **протокол** (вопрос → ответ → источник → назначение эксперта);
2. положить в программу **базу маркеров и драйверов** семи радикалов и дефолтные проверочные вопросы;
3. завести **отдельный слой гипотез ИИ** и сущность **мотивация: заявлено / гипотеза / подтверждено**;
4. встроить помощника как **неблокирующий шёпот** на интервью и как **разбор расхождений** на карточке профиля;
5. оставить вызов модели **явным, локально ключуемым, с JSON-ответом**, а заключение — за экспертом.

Пока нет пунктов 1–3, подключение модели только добавит уверенный текст к пустым счётчикам наблюдений.
