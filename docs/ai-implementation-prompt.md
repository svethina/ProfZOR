# Промпт: реализовать ИИ-помощник истинной мотивации в ProfZOR

Ниже — постановка на реализацию (разделы 5–10 спецификации `docs/ai-true-motivation.md`). Сначала прочитай весь промпт, потом делай по шагам. Не начинай с вызова API: без протокола и базы маркеров модель гадает.

Контекст продукта: локальный инструмент эксперта (`index.html`, `app.js`, `interview-logic.js`, `styles.css`, LocalStorage). Без сервера, без сборки, без Next.js/БД. Язык UI и коммитов — русский. Оценки подтверждает эксперт; программа не ставит диагноз.

Смысл «шёпота» на вкладке «Интервью»: во время живой беседы ИИ — одна короткая строка и 1–3 следующих вопроса, без панели аналитики. Разбор мотивации — только на вкладке «Карточка профиля».

---

Ты — ведущий фронтенд-разработчик. Работаем в существующем проекте ProfZOR (чистый HTML/CSS/JS, без сборки). Нужно подключить ИИ так, чтобы он помогал интервьюеру отделять заявленную мотивацию респондента от гипотезы истинной — не заменяя эксперта.

## ЦЕЛЬ

Реализовать три слоя. ИИ — третий. Первый и второй обязательны даже без ключа API: без них помощник гадает.

1. Протокол интервью (вопрос → ответ → источник → назначение эксперта).
2. База знаний 7 радикалов (маркеры, драйверы, дефолтные проверочные вопросы).
3. Клиент ИИ: явный вызов, JSON-ответ, отдельный слой гипотез, сущность мотивации (заявлено / гипотеза / подтверждено).

## ОГРАНИЧЕНИЯ

- Не ставить ИИ судьёй и не менять дисклеймер шапки.
- Не сортировать сводную таблицу по уверенности модели вместо наблюдений эксперта (допустима дополнительная колонка «гипотеза ИИ», не замена ранга).
- Не автокликать радикал по ответу модели.
- Не возвращать облачный кабинет, ленту промтов и БД.
- Не слать полное ФИО и чужие интервью «по умолчанию».
- Не генерировать заключение целиком нейросетью и не подставлять его в `#card-draft` без просмотра.
- Не имитировать мотивацию по пустому протоколу.
- Не вызывать модель на каждый `input` в textarea.
- Не впихивать ИИ четвёртой колонкой на экран интервью.
- Ключ `profzor_last_interview_v2` расширять полями, не ломать. Черновик `profzor_raw_draft_v1` в API не отправлять.
- Старые сохранения мигрировать мягко.
- Чистую логику без DOM держать в `interview-logic.js` (и новых модулях того же типа). Тесты — vitest, как сейчас.

## СЛОЙ A. ДАННЫЕ, БЕЗ КОТОРЫХ ИИ СЛЕП

Расширь модель интервью (`collectInterview` / `emptyInterview` в `app.js`; чистые функции — в `interview-logic.js`).

### A1. Протокол хода интервью

Сейчас общие вопросы — декоративная шпаргалка. Нужно:

- у вопроса поля: `asked`, `askedAt`, `answerId` (ссылка на фрагмент протокола);
- клик по вопросу = «задаю этот» (не удаление и не редактирование: во время беседы нельзя возиться со списком);
- визуально: заданный / не заданный, как чек-лист, без тяжёлого CRUD.

Проверочные вопросы радикала — тот же контракт: `asked` + уже существующий `radicalId`.

### A2. Фрагмент протокола вместо «просто текст»

Каждое наблюдение должно уметь хранить:

```
id, text, createdAt, order
radicalId            — назначение ЭКСПЕРТА (как сейчас: клик по чипу)
source               — general_question | check_question | free_note | behavior
questionId           — если ответ на конкретный вопрос
declaredMotiveHint   — если эксперт пометил фразу как заявленный мотив
socialDesirability   — none | suspected | confirmed (эксперт)
aiSuggestion         — слой ИИ, не смешивать с radicalId
```

`source: behavior` — невербалика: «долго молчал», «заговорил быстрее», «ушёл в детали процедуры».

Миграция: старый `{ text }` → фрагмент с `source: "free_note"`.

### A3. Слой предложений ИИ (отдельно от фактов)

```
ai:
  status: idle | pending | ready | error
  updatedAt
  radicalHypotheses[]    — { radicalId, confidence, markers[], quoteIds[] }
  declaredMotives[]
  trueMotiveHypothesis   — { drivers[], leadingRadicals[], tension[], confidence }
  contradictions[]       — { whatDeclared, whatObserved, whyItMatters, probeQuestion }
  coverageGaps[]
  nextQuestions[]        — 1–3 вопроса, которые можно задать сейчас
  disclaimer             — всегда: гипотеза, не диагноз
```

`radicalId` эксперта и `ai.radicalHypotheses` не перезаписывают друг друга. Если эксперт кликнул «эпилептоид», а ИИ предлагает «тревожный», оба факта видны.

### A4. Мотивация как сущность профиля

На карточке профиля, не в сырых заметках:

- `motivation.declared` — что назвал сам (вручную или принять из ИИ);
- `motivation.hypothesized` — черновик ИИ;
- `motivation.confirmed` — то, что утвердил эксперт;
- `motivation.tensions` — расхождения.

Пока `confirmed` пуст, в скачиваемом `.txt` мотивация либо отсутствует, либо помечена как «не подтверждена экспертом».

### A5. База знаний радикалов

Новый модуль `radicals-knowledge.js` (подключение как у `interview-logic.js`):

- речевые маркеры;
- поведенческие маркеры;
- типичный истинный драйвер;
- типичные социально желательные маски;
- 5–8 дефолтных проверочных вопросов на радикал.

`checkQuestionsBank` при пустом массиве сидится из этой базы (как 12 общих вопросов: не затирать непустой пользовательский список).

## СЛОЙ B. UI

Экран интервью уже три колонки. ИИ нельзя делать четвёртой колонкой.

### B1. Вкладка «Интервью» — только шёпот

Шёпот = подсказка коллеги на ухо, не кабинет аналитика.

Делай:

- галочка «задан» у общих вопросов;
- после клика по радикалу опционально 1 строка: «ИИ: скорее эпилептоид (порядок, “должен”) — принять / другой / скрыть». Фокус остаётся в заметках;
- кнопка «Подсказка ИИ» (не автозапуск на каждый символ): анализ новой дельты или всего протокола по выбору;
- блок «Что спросить дальше» — 1–3 коротких вопроса; клик копирует в заметки или в буфер; не подменяет список проверки;
- компактная строка покрытия на этой же вкладке: «нет опоры: паранойал, шизоид».

Не делай на этой вкладке: длинный разбор, графики, чат с историей, модалку поверх заметок, панель «гипотеза истинной мотивации». Это — вкладка «Карточка профиля».

### B2. Вкладка «Карточка профиля» — место для мотивации

Секция «Мотивация» над или сразу под сводной таблицей:

1. Заявленное (цитаты).
2. Гипотеза ИИ (драйверы + ведущие радикалы + уверенность).
3. Расхождения.
4. Кнопки: «Подтвердить гипотезу», «Править», «Отклонить».
5. Только после подтверждения текст попадает в заключение.

«Сформировать предварительное заключение»:
- есть `motivation.confirmed` — отдельный абзац;
- есть только гипотеза ИИ — абзац с пометкой «не подтверждено»;
- нет ничего — как сейчас, без выдумок.

Готовность: мало наблюдений или нет ни одной проверки заявленного мотива → «для вывода об истинной мотивации данных недостаточно».

### B3. Настройки ИИ (минимум)

Не отдельный продукт. Скрытый блок или маленькая панель:

- ключ API в LocalStorage, не в репозиторий;
- провайдер: сначала один, совместимый с OpenAI Chat Completions;
- тумблер «отправлять сырые заметки / только структурированный протокол»;
- тумблер «не вызывать ИИ автоматически»;
- кнопка «Собрать пакет без отправки» — копирует JSON+промпт, если нет сети или ключа.

## СЛОЙ C. КЛИЕНТ ИИ

Новые файлы, без сборки:

| Файл | Зачем |
|---|---|
| `radicals-knowledge.js` | Маркеры, драйверы, дефолтные проверочные вопросы |
| `ai-packet.js` | Канонический пакет интервью (чисто, тестируется как `interview-logic.js`) |
| `ai-prompts.js` | Системный и пользовательский промпт, JSON-схема ответа |
| `ai-client.js` | `fetch` к API, таймаут, разбор JSON, ошибки |

### C1. Пакет на вход модели

Не отправлять весь LocalStorage. В пакете:

- код/дата (без лишних ПДн);
- вопросы с флагами `asked`;
- фрагменты: текст, `source`, `questionId`, `radicalId` эксперта;
- не отправлять `motivation.confirmed` прошлого захода как истину — иначе модель поддакивает;
- инструкция: опираться только на маркеры из `radicals-knowledge`, не ставить диагноз, не выдумывать цитаты.

### C2. Ответ модели — строгий JSON, не эссе

- `declaredMotives[]`
- `radicalHypotheses[]` (не больше 3, с `quoteIds`)
- `trueMotiveHypothesis`
- `contradictions[]`
- `coverageGaps[]`
- `nextQuestions[]` (короткие, можно задать вслух)
- `insufficientEvidence` (boolean)

Если `insufficientEvidence: true` — не заполнять «истинную мотивацию» красивым текстом.

### C3. Когда вызывать

| Момент | Режим |
|---|---|
| Во время беседы | Только кнопка «Подсказка ИИ»: последняя дельта + уже известный протокол |
| Перед сменой вопроса | По желанию: «что проверить» |
| На вкладке профиля | «Разобрать мотивацию» по всему протоколу |
| Формирование заключения | Уже сохранённые `ai` + `motivation.confirmed`; новый вызов не обязателен |

### C4. Смысл системного промпта модели

Роль: ассистент эксперта по 7 радикалам.  
Задача: отличить заявленную мотивацию от гипотезы истинной.  
Запреты: диагноз, уверенность без цитат, переписывание `radicalId` эксперта, ранжирование по числу наблюдений.  
Стиль: короткие гипотезы, маркеры, один следующий вопрос.

## ПОРЯДОК РАБОТЫ (СДЕЛАЙ ПО ШАГАМ)

Каждый шаг полезен даже до ключа API.

1. Протокол и покрытие: галочки «вопрос задан», тип источника, дефолтные проверочные вопросы. Критерий: на вкладке «Интервью» видно, какие радикалы без опоры.
2. Пакет и промпт без сети: кнопка «Собрать пакет для ИИ». Критерий: пакет читается человеком, парсится тестом; в нём вопросы, ответы, назначения эксперта, пустые зоны.
3. Опциональный вызов API: ключ локально, кнопка «Подсказка», разбор JSON в `ai.*`, UI-шёпот + секция мотивации. Критерий: отказ сети не ломает интервью; предложение не пишется в `radicalId`.
4. Заключение: абзац мотивации только из `motivation.confirmed`; гипотеза ИИ отдельно и с оговоркой. Критерий: скачанный `.txt` не выдаёт догадку модели за вывод эксперта.
5. Не в этом заходе: голос/транскрипт, сравнение двух интервью, обучение на разметках, возврат поля «Цель интервью».

## ПРОВЕРКА

Ручной сценарий:

1. Новое интервью → «Расскажите немного о себе» → запись → клик по радикалу. Без ожидания сети, как сейчас.
2. «Подсказка ИИ» → гипотеза и 1 вопрос; фокус остаётся в заметках.
3. Социально желательный ответ «хочу помогать людям» → ИИ предлагает проверку примером/границей, а не верит формулировке.
4. Профиль: заявленное ≠ гипотеза; без «Подтвердить» в `.txt` нет фразы «истинная мотивация: …» как факта.
5. Нет сети / нет ключа — интервью, клики, LocalStorage работают.

Автотесты:

- вопрос без ответа не считается покрытым;
- миграция старого `observations: [{ text }]` → `source: free_note`;
- заглушка модели с лишними полями не затирает `radicalId` эксперта;
- `insufficientEvidence` не записывает `motivation.hypothesized` как готовый вывод;
- заключение: confirmed / только AI / пусто — три разных текста.

## ИТОГ, КОТОРЫЙ НЕЛЬЗЯ ПОТЕРЯТЬ

Нужно не «кнопку ChatGPT», а:

1. заметки → протокол;
2. база маркеров и драйверов + дефолтные проверки;
3. слой гипотез ИИ и мотивация: заявлено / гипотеза / подтверждено;
4. шёпот на интервью, разбор расхождений на профиле;
5. вызов модели явный, ключ локальный, ответ JSON, заключение за экспертом.

Пока нет пунктов 1–3, не подключай модель: получится уверенный текст к пустым счётчикам наблюдений.
