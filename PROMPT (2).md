Ты — ведущий fullstack-разработчик. Работаем в проекте PROFZOR (Next.js App Router + TypeScript + Tailwind + shadcn/ui + Prisma + Neon/Postgres + Auth).

ЦЕЛЬ
Сделать публичную главную страницу PROFZOR: две ленты публичных промтов/интервью:
1) свежие — по createdAt desc
2) популярные — по количеству лайков desc
Показывать только PUBLIC записи. Гость может смотреть. Авторизованный пользователь может лайкать. Создание/редактирование/удаление и переключение private/public остаются в кабинете (dashboard/CRUD) — на главной гость не создаёт контент (ссылка на вход/регистрацию).

ТРЕБОВАНИЯ К UI
- Верхняя шапка (Header):
  - логотип/название PROFZOR
  - навигация: свежие, популярные, при необходимости ещё пункты
  - справа: кнопка создать (если авторизован) или вход (если гость), меню пользователя, выход (если вошёл)
- Нижний футер (Footer):
  - копирайт: (c) PROFZOR + год
  - ссылки: по желанию (документы, контакты)
- Основная область:
  - Hero-блок: заголовок + подзаголовок + главная кнопка CTA
    - для гостя: CTA ведёт на /login (или /auth/signin)
    - для авторизованного: CTA ведёт к созданию вопроса/промта в кабинете
  - Два блока карточек:
    - свежие (примерно 10–20)
    - популярные (топ 10–20 по likesCount)
  - В карточке промта/вопроса:
    - заголовок, превью (1–2 строки), автор
    - дата (можно относительная)
    - счётчик лайков (иконка + число)
    - кнопка лайка (если пользователь авторизован)
    - бейджи видимости/категории по необходимости
- Адаптивность: корректно на мобильных.

ТРЕБОВАНИЯ К ДАННЫМ
- Сделай 2 выборки на сервере через Prisma:
  - recentPrompts: where { isPublic: true } orderBy { createdAt: "desc" } take N
  - popularPrompts: where { isPublic: true } orderBy по likesCount desc take N
- Счётчик likesCount бери через Prisma _count (не отдельным тяжёлым запросом на каждую карточку).
- Для авторизованного пользователя добавь признак likedByMe (лайкнул ли текущий пользователь).
  - Оптимально: один запрос по списку promptIds в таблицу лайков, затем Set(promptId).
